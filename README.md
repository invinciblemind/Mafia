# Мафия — эмуляция игры на C++20

Консольная эмуляция игры «Мафия» (Задание 1, 2026). Игроки — иерархия классов по ролям; ходы каждого игрока исполняются либо в отдельных нитях (`std::thread`), либо корутинами в одном потоке; общие структуры хранятся в собственном умном указателе `SharedPtr`. Любого из игроков можно взять под управление с клавиатуры, набор ролей задаётся YAML-файлом, ход игры пишется в файлы логов.

## Сборка и тесты

**Требования:** CMake ≥ 3.20 и компилятор с поддержкой C++20, включая концепты, корутины и `<ranges>` (проверено на macOS, AppleClang 15). Сторонних библиотек нет — разбор YAML написан самостоятельно.

```bash
cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Исполняемый файл: `build/mafia`.

> **Тесты нужно собирать без `-DCMAKE_BUILD_TYPE=Release`.** Они проверяют условия через `assert`, а в Release он отключён (`NDEBUG`): тесты либо перестанут компилироваться, либо станут бессмысленными. Для самой игры любая конфигурация подходит: `cmake -S . -B build-rel -DCMAKE_BUILD_TYPE=Release && cmake --build build-rel --target mafia`. Для тестов используйте конфигурацию по умолчанию или `-DCMAKE_BUILD_TYPE=Debug`.

Проверка санитайзерами (рекомендуется после правок в многопоточном коде):

```bash
# память и неопределённое поведение
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -g" -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined"
# гонки данных
cmake -S . -B build-tsan -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=thread -g" -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=thread"
```

## Запуск

```bash
./build/mafia --players 10 --interactive --open-announcements --full-log
```

| Параметр | Описание |
|---|---|
| `--players N` | **обязательный**, количество игроков, `N > 4` |
| `--interactive` | один случайный игрок управляется человеком (входит в `N`) |
| `--open-announcements` | Ведущий объявляет полную роль и обстоятельства ночи (по умолчанию — закрытые: только лагерь) |
| `--full-log` | подробный внутренний лог раунда в консоль (голоса, цели действий, раздача ролей) |
| `--roles-config FILE` | YAML-файл с набором ролей (по умолчанию: мафия, мирные, Доктор, Комиссар, Маньяк) |
| `--mafia-divisor K` | `k` из формулы `floor(N/k)`, `k ≥ 3`; перекрывает значение из конфига (по умолчанию 3) |
| `--coroutines` | исполнять ходы корутинами в одном потоке вместо нитей |
| `--log-dir DIR` | куда писать файловые логи (по умолчанию `./logs`) |
| `--no-file-log` | не писать файловые логи |
| `--help` | справка |

При ошибке параметров (нет `--players`, `N ≤ 4`, нечитаемый конфиг, слишком мало игроков для выбранных ролей) программа печатает понятное сообщение и завершается с кодом 1.

Примеры:

```bash
./build/mafia --players 8                                           # все боты, закрытые объявления
./build/mafia --players 12 --roles-config config/roles_extended.yaml --open-announcements
./build/mafia --players 9 --interactive --coroutines                # вы играете, ходы на корутинах
./build/mafia --players 20 --no-file-log --full-log
```

Фрагмент вывода (открытые объявления):

```
=== День 1 ===
Голосование завершилось вничью, Ведущий бросает монетку.
Казнён по результатам голосования: Player6 -- роль: Маньяк

=== Ночь 1 ===
Реаниматор воскресил Player3 -- роль: Сержант.
Вор заблокировал Player2: ночное действие не сработало.
Этой ночью никто не погиб.
...
=== Игра окончена ===
Победили мирные жители!
```

## Правила игры

**Число мафии** — `max(1, floor(N / k))`, `k ≥ 3`. Остальные места занимают особые роли из конфигурации и мирные жители.

**Ход игры:** раздача ролей → **день** (каждый живой голосует против одного игрока, казнён набравший больше голосов; при ничьей Ведущий бросает монетку) → **ночь** → снова день. Игра заканчивается, как только выполнено условие победы (оно проверяется и после дня, и после ночи).

### Роли

| Роль | Лагерь | Ночью | Особенности |
|---|---|---|---|
| Мирный житель | мирные | — | только голосует |
| Доктор | мирные | лечит одного (можно себя) | не лечит одного и того же две ночи подряд; лечение защищает от всех покушений на этого игрока сразу |
| Комиссар | мирные | проверяет **или** стреляет | Маньяк при проверке выглядит мирным; бот стреляет в изобличённую мафию и голосует против неё |
| Мафия | мафия | убивает единогласным решением банды | решение озвучивает **Босс** — живой член банды с наименьшим id (после его гибели Босс переходит к следующему); остальные в ночь не ходят |
| Маньяк | одиночка | убивает любого | ограничений на повтор цели нет |
| **Сержант** | мирные | — | знает Комиссара, видит результаты его проверок; Комиссар знает Сержанта; при гибели (казнь или убийство) Комиссара занимает его место; Сержанта нет в списках целей Комиссара, а Комиссара — в списке голосования Сержанта |
| **Реаниматор** | мирные | воскрешает одного | ходит **последним**, когда известно, кто погиб этой ночью (после лечения Доктора): видит имена погибших без ролей и может вернуть одного из них; казнённых днём и погибших в прошлые ночи воскресить нельзя; одного игрока — только один раз; ход необязателен |
| **Вор** | мафия | блокирует | мафиози; вместо участия в выборе жертвы блокирует ночное действие особой роли мирного (Доктор, Комиссар, Реаниматор) — оно не срабатывает; занимает одно из мест мафии по формуле; Босс выбирается среди обычных мафиози, а если их нет, Вор стреляет сам; Комиссар видит его как мафию |

### Условия победы
- **Мирные** — убиты все мафиози и Маньяк.
- **Маньяк** — мафии нет, а из мирных жив не более одного (в том числе когда Маньяк остался один).
- **Мафия** — численное преимущество над всеми остальными живыми (мирные плюс Маньяк); при равенстве — только если Маньяка уже нет в живых.

### Порядок ночи
1. Все, кроме Реаниматора, ходят одновременно.
2. Блокировка Вора отменяет ходы заблокированных особых ролей мирных.
3. Применяются лечение и убийства.
4. Ходит Реаниматор (если жив к началу ночи и не заблокирован). Если его самого убили этой ночью, он всё равно успевает назвать кого-то, в том числе себя.
5. Если Комиссар погиб (и не был воскрешён), Сержант становится Комиссаром.

## Интерактивный режим

С `--interactive` один случайный игрок (имя вида `Player3`) передаётся вам. Ведущий сообщает вашу роль и показывает подсказку в начале каждого вашего хода: что требуется и список доступных целей по `id`.

- **Голосование и ночные действия:** введите `id` игрока из списка. Некорректный ввод переспрашивается.
- **Комиссар:** сначала слово `check` или `shoot`, затем цель.
- **Реаниматор:** `id` из списка погибших или `-`, чтобы никого не воскрешать.
- **Приватные сообщения** (`[Только для вас]`): результаты проверок Комиссара (и его Сержанта, плюс сводка проверок по утрам), знание пары Комиссар/Сержант, команда мафии и Босс, повышение Сержанта, воскрешение, «ваше действие не сработало».
- Мафиози, не являющийся Боссом, ночью не ходит: Ведущий напоминает, кто Босс. Вор ходит всегда (блокирует).
- Если вас убили или казнили, об этом сообщается отдельно, и вы продолжаете наблюдать за игрой.
- Если поток ввода закончился (например, ввод из файла), игра не зависает: берётся значение по умолчанию (первая цель; пропуск для необязательных ходов).

## Конфигурация ролей (YAML)

Какие особые роли участвуют в игре, задаётся файлом (`--roles-config`). Мафия и мирные есть всегда и перечислять их не нужно (можно, но они ни на что не влияют).

```yaml
# config/roles_extended.yaml
mafia_divisor: 3
roles:
  - doctor
  - commissar
  - maniac
  - sergeant      # знает Комиссара, при его гибели занимает его место
  - resuscitator  # воскрешает погибших этой ночью
  - thief         # мафиози, блокирует способности мирного
```

- **Ключи:** `mafia_divisor` (целое, ≥ 3) и `roles` (список). Других ключей нет, неизвестный ключ — ошибка.
- **Имена ролей** (регистр неважен, можно по-русски): `doctor`/`доктор`, `commissar`/`комиссар`, `maniac`/`маньяк`, `sergeant`/`сержант`, `resuscitator`/`реаниматор`, `thief`/`вор`.
- Если ключа `roles` нет — набор по умолчанию (Доктор, Комиссар, Маньяк). Если есть — включены **ровно перечисленные** роли (`roles: []` — только мафия и мирные).
- Каждая особая роль — не более одного игрока. Вор не добавляется сверх мафии, а занимает одно из её мест.
- **Поддерживаемый синтаксис YAML** (парсер собственный, без зависимостей): комментарии `#`, `ключ: значение`, блочные списки `- элемент`, inline-списки `[a, b]`, кавычки. Вложенные структуры и табуляции в отступах не поддерживаются. Ошибки сообщаются с именем файла и номером строки.
- Предупреждения (не ошибки): Реаниматор без Маньяка и Комиссара (по правилам он вводится при двух и более стреляющих сторонах); Сержант без Комиссара.
- Минимальное число игроков зависит от набора: `мафия + количество особых ролей ≤ N` (расширенному набору при `k = 3` нужно минимум 7 игроков).

Готовые примеры: [`config/roles_basic.yaml`](config/roles_basic.yaml), [`config/roles_extended.yaml`](config/roles_extended.yaml).

## Режимы вывода и файловые логи

**Объявления Ведущего:**
- *Закрытые (по умолчанию):* при казни или гибели называется только лагерь («мафия»/«мирные»; Маньяк объявляется мирным, так как в правилах всего два публичных лагеря). Обстоятельства ночи скрыты: неизвестно, кто стрелял, кого спас Доктор, почему никто не погиб.
- *Открытые (`--open-announcements`):* называется полная роль, а также что сделали Доктор, Вор и Реаниматор.

**Лог в консоль:** по умолчанию краткий (игровой). `--full-log` добавляет раздачу ролей, голоса «кто за кого» и цели ночных действий.

**Файловые логи** (всегда содержат полную информацию независимо от режима объявлений):

```
logs/game_<ГГГГММДД_ЧЧММСС>/
  setup.txt        раздача ролей
  round_01.txt     раунд 1: голоса, подсчёт, казнь, ночные действия, итоги ночи
  round_02.txt     ...
  summary.txt      результат, число раундов, статистика по каждому игроку
```

Статистика игрока: роль и лагерь, статус (жив / раунд и причина гибели), голосов отдано (в том числе против мафии), голосов получено, воскрешений. Папка создаётся автоматически; если создать её нельзя, игра продолжается без файловых логов с предупреждением. Каталог `logs/` добавлен в `.gitignore`.

## Нити и корутины

Решение каждого игрока в рамках одной фазы (голосование или ночной ход) вычисляется отдельно, Ведущий собирает результаты и только потом разрешает фазу.

| Режим | Как исполняются ходы | Как ждёт человек |
|---|---|---|
| **Нити** (по умолчанию) | по `std::thread` на игрока, `join` в конце фазы | блокируется в своей нити на вводе, остальные нити уже завершены |
| **Корутины** (`--coroutines`) | по корутине `Task<T>` на игрока, один поток, кооперативный планировщик `run_all` | корутина человека приостанавливается на `co_await input.read_line()`; боты завершаются первыми, строка читается, когда больше нечего выполнять |

Результат игры не зависит от режима (проверено тестами). Гонок данных в режиме нитей нет: каждая нить пишет в свой слот результата и работает только со своим игроком, счётчик `SharedPtr` атомарный, генераторы случайных чисел `thread_local`.

## Архитектура

```
include/mafia/ , src/
  action.hpp          PlayerId, ActionType, NightAction — «словарь» решений игроков
  role.hpp            Role, Team, team_of(), acts_at_night(), role_name()
  shared_ptr.hpp      SharedPtr<T> (п.1)
  coroutines.hpp      Task<T>, InputBroker, run_all, run_blocking (п.4)
  player.hpp          абстрактный Player: vote()/act() + async-варианты
  game_view.hpp       GameView — всё, что игрок видит на своём ходу
  concepts.hpp        PlayerLike, TownPlayer, MafiaPlayer, NightActivePlayer, make_player, take_night_turn (п.3)
  game_master.*       Ведущий: раздача ролей, день, ночь, победа, замена Сержанта
  game_logger.*       файловые логи (п.3)
  role_config.*       RoleConfig и YAML-парсер (п.5)
  main.cpp            параметры, весь консольный вывод, приватные сообщения человеку
  roles/              civilian doctor commissar mafia maniac sergeant resuscitator thief
                      mafia_council   — общее состояние банды (SharedPtr)
                      commissar_intel — общее досье Комиссара и Сержанта (SharedPtr)
                      role_utils      — выбор цели ботом и корутинные запросы к человеку
config/               примеры YAML
tests/                10 исполняемых тестов
```

Ключевые идеи:

- **Игрок только принимает решение.** `Player::vote/act` получают `GameView` (живые игроки, номер раунда, канал ввода) и **возвращают** результат. Применяет его только `GameMaster` — «все события идут через Ведущего». Игроки ссылаются друг на друга числом `PlayerId`, а не указателем.
- **`GameMaster`** хранит `vector<SharedPtr<Player>>` (индекс = `PlayerId`). `play_day()` и `play_night()` вызываются отдельно (`play_round()` — удобная обёртка); `check_winner()` считает живых по лагерям через `std::ranges`.
- **Роли с общим состоянием** получают его при создании через `SharedPtr`: банда мафии (`MafiaCouncil`) и пара Комиссар/Сержант (`CommissarIntel`). Босс не хранится, а вычисляется каждую ночь.
- **Замена Сержанта:** `GameMaster` подменяет его объект в слоте новым `Commissar` с тем же id, именем, признаком «человек» и общим досье.
- **Один код для человека и бота:** у человека синхронные `vote()/act()` вызывают то же корутинное `vote_async()/act_async()` через `run_blocking`, поэтому правила роли (например, список допустимых целей) не дублируются.
- **Концепты** проверяют контракт роли при компиляции (`static_assert` в тестах); игровой цикл работает через базовый `Player` и виртуальные методы.
- Приоритет настроек: значения по умолчанию → YAML-файл → флаги командной строки (например, `--mafia-divisor` перекрывает значение из YAML).

## Тестирование

10 исполняемых наборов, около 100 сценариев и набор `static_assert`:

| Набор | Что проверяет |
|---|---|
| `SharedPtrTests` | счётчики, копирование/перемещение, `reset`/`swap`, сравнения, многопоточный стресс |
| `PlayerRoleTests`, `MafiaManiacTests` | правила Мирного, Доктора, Комиссара, Мафии и Маньяка; Босс и его смена |
| `GameMasterTests` | раздача ролей, формула числа мафии, лечение и убийства, проверки Комиссара, голосование и ничья, условия победы, раунды |
| `InteractiveTests` | запросы к человеку на подставных потоках, повторный запрос при ошибке, EOF |
| `GameLoggerTests` | создание вложенных папок, файл на раунд, содержимое логов, ошибка создания папки |
| `ConceptTests` | концепты на всех ролях и на «чужих» типах (`static_assert`) |
| `CoroutineTests` | `Task`, вложенные `co_await`, исключения, порядок «человек ждёт — боты готовы», равенство режимов нитей и корутин |
| `ExtraRoleTests` | Вор, Реаниматор, Сержант: блокировки, воскрешения и все их ограничения, замена Комиссара, исключения из списков, раздача по конфигу, полные партии в обоих режимах |
| `RoleConfigTests` | синтаксис YAML, русские имена, все виды ошибок с номерами строк, загрузка из файла, примеры из `config/` |

Тесты детерминированы там, где это возможно: роли проверяются на минимальных составах, где выбор бота вынужден, а для Ведущего используется тестовый игрок со скриптом ходов (`ScriptedPlayer`), который можно подставить через конструктор `GameMaster(std::vector<SharedPtr<Player>>)`.

## Принятые решения и упрощения

Правила местами неоднозначны, поэтому приняты следующие трактовки:

- **Ничья при голосовании** — монетка (из двух допустимых правилами вариантов; игра гарантированно движется вперёд).
- **Единогласность мафии** моделируется тем, что решает только Босс, остальные «воздерживаются»; настоящих переговоров между ботами нет.
- **Равенство мафии и не-мафии при живом Маньяке** не даёт победы мафии (п.5 правил мафиози).
- **Маньяк** в закрытых объявлениях называется «мирным».
- **День всегда идёт первым**, включая первый цикл; номер раунда увеличивается днём, ночь принадлежит тому же раунду.
- **Нить создаётся на фазу**, а не на всю игру.
- **Вор** — мафиози, который не участвует в выборе жертвы; блокирует только особые роли мирных.
- **Реаниматор** может назвать себя, если его убили этой ночью.
- Бот-Комиссар использует результаты проверок (стреляет в изобличённую мафию), бот-Сержант голосует против известной мафии. Остальные боты выбирают цели случайно.

## Известные ограничения

- Не реализован пункт 6 (ИИ-агент); боты принимают решения случайно, без анализа «доверия» и речей.
- Мафиози-человек, не являющийся Боссом, ночью не ходит (следствие упрощения про единогласие).
- Каждая особая роль — не более одного игрока; в отчёте ночи по одному полю на тип действия.
- Сборка проверялась только на macOS (AppleClang 15). В логгере используется `localtime_r` из POSIX, под Windows потребуется правка.
- Разбор числовых параметров командной строки нестрогий (`atoi`).
- В `tests/test_game_master.cpp` компилятор предупреждает (`-Wswitch`), что `switch` по `Role` не перечисляет новые роли: на результат тестов это не влияет.
- `Commissar::checked_` (эвристика бота «кого я уже проверял») частично дублирует досье `CommissarIntel`; оставлено, чтобы роль можно было проверять отдельно от Ведущего.

## Как добавить новую роль

1. Добавить значение в `Role` и ветки в `team_of`, `acts_at_night`, `role_name` ([role.hpp](include/mafia/role.hpp)); компилятор подскажет остальные места, где `switch` по `Role` нужно дополнить.
2. Создать класс-наследник `Player` в `include/mafia/roles/` и `src/roles/` со `static constexpr Role kRole`, переопределить `vote()`/`act()`; для человека — `vote_async()`/`act_async()` (используйте `detail::prompt_for_target_async`). Проверить контракт: `static_assert(PlayerLike<НоваяРоль>)` в [tests/test_concepts.cpp](tests/test_concepts.cpp).
3. Если у роли новый тип ночного действия — добавить его в `ActionType` и обработать в `GameMaster::play_night()`. Роль, которой нужно знать итоги ночи, ходит на втором этапе (`acts_after_resolution()`).
4. Подключить роль в `GameMaster::assign_roles`, флаг в `RoleConfig` и имя в `role_config.cpp`.
5. Добавить файлы в `CMakeLists.txt` и тесты.
